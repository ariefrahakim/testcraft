## Lesson 10: AI in the PR Review Loop

Claude reviews every pull request before it merges. The review checks:
- Does the implementation match the spec?
- Are all ACs covered by tests?
- Any security concerns?
- Any missing error cases?

### GitHub Actions: Automated PR Review

The `.github/workflows/ci.yml` already includes the CI gate. Add AI review on top:

Create `.github/workflows/pr-review.yml`:

```yaml
name: AI PR Review

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  ai-review:
    runs-on: ubuntu-latest
    permissions:
      pull-requests: write
      contents: read

    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Get changed files
        id: changed
        run: |
          git diff --name-only origin/${{ github.base_ref }}...HEAD > changed-files.txt
          cat changed-files.txt

      - name: Find related spec
        id: spec
        run: |
          # Look for spec referenced in changed files
          SPEC=""
          while read file; do
            if grep -q "Spec:" "$file" 2>/dev/null; then
              SPEC=$(grep "Spec:" "$file" | head -1 | sed 's/.*Spec: //' | tr -d '\n')
            fi
          done < changed-files.txt
          echo "spec=$SPEC" >> $GITHUB_OUTPUT

      - name: Post review checklist
        uses: actions/github-script@v7
        with:
          script: |
            const spec = '${{ steps.spec.outputs.spec }}'
            const body = `## AI Review Checklist

            **Spec**: \`${spec || 'not detected — add Spec: comment to changed files'}\`

            ### Implementation Gate
            - [ ] All spec ACs have corresponding code changes
            - [ ] No business logic in controllers (services only)
            - [ ] No client-provided prices or sensitive values trusted
            - [ ] TypeScript compiles cleanly (verified by CI)

            ### Test Gate
            - [ ] New AC → new test in \`tests/e2e/specs/\` or \`apps/api/test/\`
            - [ ] Playwright \`data-testid\` attributes added for new UI elements
            - [ ] No hard waits (\`waitForTimeout\`) in Playwright tests
            - [ ] All new tests reference their Qase TC number in the title

            ### Security Gate
            - [ ] Auth guard applied (\`@Roles\` or \`@Public\` explicit)
            - [ ] IDOR: users can only access their own resources
            - [ ] No sensitive fields in API responses (password, tokens, answer keys)
            - [ ] \`docs/openapi.json\` updated if endpoints changed

            ### Documentation Gate
            - [ ] Spec status updated to \`IMPLEMENTED\`
            - [ ] Spec AC table has Qase IDs filled in
            - [ ] \`CLAUDE.md\` updated if new pattern established
            - [ ] Intent moved to \`docs/intents/done/\`

            ---
            *This checklist is generated by the AI-Native SDLC pipeline.*
            *All boxes must be checked before merge.*`

            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body
            })
```

## Lesson 11: Hooks as Approval Gates

Hooks run automatically when you take certain actions. They act as guardrails — preventing broken code from moving forward in the pipeline.

### Pre-commit Hook (blocks commit if tests fail)

Create `scripts/hooks/pre-commit`:
```bash
#!/bin/bash
# Pre-commit hook — runs on every git commit
# Blocks commit if TypeScript or lint fails

echo "🔍 Running pre-commit checks..."

# TypeScript check
echo "→ TypeScript..."
npm run typecheck --workspaces --if-present
if [ $? -ne 0 ]; then
  echo "❌ TypeScript errors found. Fix before committing."
  exit 1
fi

# Lint
echo "→ Lint..."
npm run lint --workspaces --if-present
if [ $? -ne 0 ]; then
  echo "❌ Lint errors found. Fix before committing."
  exit 1
fi

# OpenAPI sync check
echo "→ OpenAPI spec..."
npm run docs:openapi 2>/dev/null
if ! git diff --exit-code docs/openapi.json > /dev/null 2>&1; then
  echo "❌ docs/openapi.json is out of sync. Run 'npm run docs:openapi' and commit the result."
  exit 1
fi

echo "✅ All pre-commit checks passed."
exit 0
```

Install:
```bash
cp scripts/hooks/pre-commit .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

### Pre-push Hook (runs E2E smoke tests before pushing)

Create `scripts/hooks/pre-push`:
```bash
#!/bin/bash
# Pre-push hook — runs smoke tests before pushing to remote
# Catches obvious regressions before CI sees them

echo "🧪 Running smoke tests before push..."

# Check if apps are running
if ! curl -sf http://localhost:4001/api/v1/health > /dev/null 2>&1; then
  echo "⚠️  API not running — skipping E2E smoke tests"
  echo "   Start with: npm run dev"
  exit 0
fi

# Run smoke tests only (fast)
cd tests/e2e && npx playwright test --grep @smoke --reporter=list
if [ $? -ne 0 ]; then
  echo "❌ Smoke tests failed. Fix before pushing."
  exit 1
fi

echo "✅ Smoke tests passed. Pushing..."
exit 0
```

### Claude Code Hooks (in .claude/settings.json)

Claude Code hooks run Claude commands automatically on events.
These need to be set by you in `.claude/settings.json` (Claude cannot write this file itself):

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "cd /Users/ariefrahman/Desktop/testcraft && npm run typecheck --workspaces --if-present 2>&1 | tail -5"
          }
        ]
      }
    ]
  }
}
```

This runs TypeScript check after every file edit — Claude sees errors immediately and fixes them in the same session.

## Lesson 12: CI/CD Integration and Deployment

### Full Pipeline Flow

```
Developer writes intent.md (Stage 1)
    ↓
Claude creates spec.md (Stage 2)
    ↓
Claude implements with plan mode (Stage 3)
    ↓
Tests run + feedback loop (Stage 4)
    ↓
git push origin main
    ↓
GitHub Actions: CI pipeline
  ├── lint ✓
  ├── typecheck ✓
  ├── api-test ✓
  ├── web-build ✓
  ├── marketing-build ✓
  └── e2e ✓
    ↓
All green → AI PR review posted (pr-review.yml)
    ↓
PR merged to main
    ↓
deploy-vps.yml triggers:
  ├── Build Docker images (api, web, marketing)
  ├── Push to GitHub Container Registry
  └── SSH deploy to VPS:
      ├── docker compose pull
      ├── docker compose up -d
      ├── Run migrations
      └── Health check
    ↓
Production live ✅
```

### VPS Deployment (Manual Trigger)

```bash
# Trigger a manual deploy
gh workflow run deploy-vps.yml -f environment=production

# Watch it run
gh run watch

# Or SSH directly
./scripts/deploy.sh production
```

### Rollback

If a deployment breaks production:
```bash
# SSH to VPS and rollback to previous image
ssh $VPS_USER@$VPS_HOST \
  "cd /opt/testcraft && IMAGE_TAG=<previous-sha> docker compose -f docker-compose.prod.yml up -d"
```

Or in GitHub Actions:
```bash
# Re-run the previous successful deploy workflow
gh run rerun <previous-run-id>
```

### Environment Promotion

```
Feature branch → opens PR → CI runs → AI review checklist
    ↓ merge
main → CI runs → auto-deploys to VPS production
```

No staging environment currently. If needed, add a `staging` branch and a separate `deploy-staging.yml` workflow.

## Complete SDLC Summary

| Stage | Owner | Input | Output | Gate |
|---|---|---|---|---|
| 1 Plan | Human | User need | `intent.md` | Human review |
| 2 Design | `be-agent`/`fe-agent` | `intent.md` | `spec.md` | Spec review |
| 3 Build | `be-agent`/`fe-agent` | `spec.md` | Code + tests | Plan approval |
| 4 Test | `qa-playwright-agent` | Code | Test results → Qase | All ACs green |
| 5 Deploy | CI/CD | Green tests | Production | All CI gates |

Every stage has a gate. Nothing skips the gate.
